## Two improvements

### 1. Yields scale inversely with property value

**Symptom:** All properties — cheap terraces and luxury homes alike — roll a flat 6–15% yield. Real markets show prime/expensive stock yielding less than budget stock.

**Fix in `src/lib/engine/market.ts` `generateRandomProperty` (line 19):**
- Replace the flat `6 + Math.random() * 9` with a value-anchored band. Map the property's pound value through `getPropertyValueRangeForLevel`-style buckets to a centre yield, then add ±1.5% jitter:

```text
≤ £75k        → centre 11% (band ~9.5–12.5%)
£75k–£150k    → centre 9%
£150k–£300k   → centre 7.5%
£300k–£600k   → centre 6%
£600k–£1.2m   → centre 5%
> £1.2m       → centre 4% (band ~2.5–5.5%)
```

- Implement as a small pure helper `yieldForValue(valuePennies: number): number` colocated in `market.ts` so the test surface is obvious. Clamp the final output to `[2.5, 14]`.
- `baseMonthlyIncome` continues to derive from `(price * yield/100) / 12` so rent at the agent already reflects the new band — no other call sites change.

**Migration:** legacy properties already on the player's books keep their stored `yield`. New stock generated by the inventory top-up loop in `gameStore.ts` (which calls `generateRandomProperty`) automatically uses the new curve. No save migration needed.

**Display:** the existing yield pill on `property-card.tsx` and `estate-agent-window.tsx` keeps working unchanged — values just trend lower for pricier homes.

### 2. Click an auction listing to watch live bidding

**Symptom:** When the player lists their own property for auction it sits in the "Your Auction Listings" panel as a static card. There's no way to open it and see bids arriving — they just discover the result via toast next month.

**Fix in `src/components/ui/auction-house.tsx`:**
- Make each row in the "Your Auction Listings" block (lines 781-806) a clickable card. On click, open a new modal (`SellerAuctionWatcher`) that shows live bid activity for that listing.
- Promote the existing per-listing simulation (currently only ticking inside the monthly `useEffect` at line 224) to a faster heartbeat **while the watcher is open**:
  - Add per-listing `bidHistory: Array<{ bidder, amount, timestamp }>` to the `AuctionListing` interface (line 15).
  - When the watcher modal mounts, start a `setInterval` (~2s) that rolls a bid: 60% chance to bump `highestBid` by 0.5–3% of value, with a random bidder name from the existing `bidderNames` pool, and pushes onto `bidHistory`. Pause/clear when the modal closes.
- Watcher modal contents:
  - Header: property name, reserve, guide, time-to-auction in months.
  - Live "Current bid" pill (re-using the green styling on line 794).
  - Scrolling bid list (newest at top): `· {bidder} bid £{amount}` with a relative timestamp.
  - Auctioneer ticker line ("Going once at £…") that updates whenever a new bid lands.
  - Footer with a "Withdraw listing" button (reuses the existing listing removal pathway — drop the entry from `setListings`).
- Settlement: when `monthsPlayed` reaches `auctionMonth`, the existing completion block (lines 248-275) still runs and the watcher modal switches to a "SOLD £X" / "Reserve not met" panel until the user closes it.

No store changes needed — `listings` already lives in component state. The `AuctionListing` interface gains one field (`bidHistory`).
